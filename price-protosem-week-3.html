02 — Five Days, One Connected Journey

A step-by-step account of systems exploration, software delivery, and physical circuit assembly.

DAY 01

Preparing the Machine

Focus: Operating system installation and system setup

Before writing programs, I explored the environment in which they run. With Linga's guidance, I learned about the system boot process, installation media and the steps involved in installing an operating system. I also explored the basic configuration needed after installation.

This session helped me understand that a working computer is not just a device we use; it is a system that must be prepared and configured correctly.

Field note: Every development environment begins with a properly prepared system.
Hardware Boot Sequence Architecture SYSTEM EXECUTION PIPELINE
STAGE 01
Power / POST

Power-On Self-Test verifies CPU, RAM & core hardware integrity.

STAGE 02
UEFI / BIOS

Locates valid boot media and executes Master Boot Record/ESP.

STAGE 03
Bootloader

Loads kernel image (e.g. GRUB) into system memory space.

STAGE 04
Kernel Init

Mounts root filesystem and initializes hardware drivers.

STAGE 05
Userspace / OS

Spawns system services, shells, and user environments.

DAY 02

Inside the Linux Terminal

Focus: Commands, files and a terminal-based game

I moved into the Linux environment and explored how to interact with a system through its terminal. Instead of relying entirely on graphical interfaces, I worked with commands, file management and the execution of a terminal-based game.

The experience connected command-line fundamentals with practical programming. I also began exploring how the game could be deployed through Vercel.

Field note: The terminal turns instructions into direct interaction with the system.

DAY 04

Understanding the Electrical Side

Focus: Electronic components and circuit fundamentals

With Brahma's guidance, I began exploring the fundamentals of electronics. The session introduced basic components, their practical applications and the role they play in simple circuits.

Working with breadboards, LEDs and electronic components helped connect theoretical concepts with physical behavior. I also participated in practical testing involving capacitor voltage limits and power supply characteristics.

Field note: A circuit is more than a collection of components; every connection affects how the system behaves.
Core Electrical Components Identified LABORATORY EXPERIMENTATION
Breadboard
Solderless prototyping grid with internal spring clips.
LEDs
Semiconductor light emitters requiring polarity respect (Anode/Cathode).
Resistors
Limiting current flow to protect sensitive components from burn-out.
Capacitors
Charge storage & voltage filtering; verified breakdown voltage ratings.
DAY 05

Making the Circuit Real

Focus: Practical electronics and circuit prototyping

I continued working with basic electronic components and learned how to identify them, understand their connections and assemble simple circuits. The hands-on work included a perfboard prototype using an LED indicator, resistor and tactile switch.

The session made the relationship between components, connections and outputs easier to understand. It also provided an introduction to the care required when moving from a temporary circuit arrangement toward a more permanent prototype.

Field note: A small circuit is a practical lesson in how individual parts work together as a system.

Common Pattern

03 — The Engineering Connection

The week's activities may appear to belong to different areas, but they follow a common pattern: Prepare → Execute → Deploy → Connect → Test.

PREPARE

Configure Environment

Configure the operating system, verify BIOS/UEFI parameters, and prepare the development environment.

EXECUTE

Run Programs

Use Linux terminal commands, manage files, and execute the terminal-based game engine.

DEPLOY

Publish to Cloud

Explore making the project accessible beyond the local machine through cloud hosting on Vercel.

CONNECT

Workflow & Hardware Assembly

Organize the learning workflow with Obsidian and assemble discrete electronic components into circuits.

TEST

Validate System Behavior

Observe how circuits, components, power supplies, and software instructions behave in practical reality.

This sequence helped me see computing as a complete process, extending from the machine and its software to the physical world.

05 — Lab Notes: What I Would Explore Further

This week also raised questions worth carrying into future projects and hardware-based prototyping:

How can the operating system and development environment be configured more efficiently?

Investigating automation scripts, dotfile managers, and reproducible environment containers.

How can project deployment and weekly documentation become more repeatable?

Exploring automated CI/CD pipelines connecting Obsidian vault exports directly to Vercel builds.

How do component values and circuit connections influence the final output?

Measuring voltage drops, RC time constants, and signal damping across varied resistance levels.

How can software logic eventually control a physical circuit?

Connecting microcontrollers (Arduino/ESP32) GPIO pins with digital control loops and sensor inputs.

* These questions provide a bridge between the systems work completed this week and the hardware-based prototyping to come.
Closing Perspective

06 — The Week's Closing Reflection

Week 03 changed how I look at the technology behind a working product. A program depends on an environment in which it can run, a deployment process through which people can access it, and—when software interacts with the physical world—hardware that responds to its instructions.

From installing an operating system to testing a circuit, each activity reinforced the value of understanding the parts before bringing them together.

The biggest takeaway: Building technology is not just about making something work once. It is about understanding the system, testing the details and creating a process that can be repeated.
